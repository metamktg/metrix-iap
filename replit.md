# Metrix

Metrix IAP is an ad-performance analysis platform: agencies connect Meta ad accounts (live OAuth or manual CSV/creative upload), run analysis, and get AI-generated strategy/briefs plus reporting — all backed by Supabase.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm --filter @workspace/api-server run test` — API server tests (vitest; includes password-reset cleanup against dev Replit Postgres)
- `pnpm --filter @workspace/scripts run test` — scripts unit tests (vitest, no DB needed): meta-ads-export backfill rules, LittleData CSV parsing/aggregation/reconciliation
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/scripts run check:api-codegen-drift` — build-safety gate (validation step `api-codegen-drift`): regenerates codegen into a throwaway sandbox (`ORVAL_DRIFT_OUT`, honored by `lib/api-spec/orval.config.ts`), fails loudly if committed generated types (`lib/api-zod`, `lib/api-client-react`) drifted from `openapi.yaml`, then runs the full `pnpm run typecheck` (rebuilds composite libs first). Catches stale generated API types that pass an isolated per-artifact typecheck but break the real build. NEVER regenerate the live `lib/*/src/generated/**` from a validation: orval's `clean: true` deletes/rewrites files the Vite dev servers watch, crashing live browser sessions with mass HMR invalidations. Validations that rebuild the shared libs (drift check's typecheck phase + build smokes) still serialize through a cross-process lock (`scripts/src/lib/validation-lock.ts`); new lib-touching validation scripts must wrap that phase in `withValidationLock`.
- `pnpm --filter @workspace/scripts run check:interaction` — validation step (`interaction`) and CI-adjacent design gate: fails on an affordance that only exists on hover (invisible on touch), a control whose hit area is under the WCAG 2.2 AA 24px target size, and a `<button>` nested inside a `<button>` (invalid HTML — the browser drops one, so one action silently stops working). Controls between 24px and 40px are reported as a NOTE, not a failure: above the AA floor, below touch-comfort, a density choice.
- `pnpm --filter @workspace/scripts run check:friction` — READ-ONLY operator gate, NOT a `.replit` validation (it needs a running dev server, same as `check:accessible-names` / `check:chart-geometry` / `check:unexplained-dashes`; start one with `PORT=5178 BASE_PATH=/ pnpm --filter @workspace/metrix-iap run dev`). Walks every route `navTree.ts` and `App.tsx` declare — legacy redirect sources excluded, so a finding is filed against the page that produced it — for two fixture accounts at 1440 and 390 px, and splits findings in two. **Defects** are never baselined and must stay at zero: an uncaught exception or console error, horizontal overflow, a `<button>` nested in a `<button>`, and copy the signal/coverage rework retired. **Ratchets** live per route in `scripts/src/check-friction.baseline.json` (regenerate with `-- --write-baseline`): first-layer warning boxes, warning glyphs, and prose over the rulebook's 220 characters. A route may lower a count freely; raising one fails, same contract as `check:disclosure-rulebook`. No-data phrases are a SET per route, not a count — "No creative scan yet" on the Creative Scan page is the loop's honest empty state, the same sentence on Analysis Overview means a surface stopped reading a dataset its siblings still have, and only phrase-plus-route separates them. Exit 0 clean / 1 findings / 2 could not reach the server (nothing checked — not a verdict).
- `pnpm --filter @workspace/scripts run check:locator-ambiguity` — validation step (`locator-ambiguity`) and a CI step: Playwright matches `getByRole(role, { name })` by case-insensitive SUBSTRING unless `exact: true` is passed, so giving `SectionCard`'s header an `aria-label` of `"Collapse section: <title>"` made thirteen existing spec locators resolve to two elements each — every one a strict-mode violation. The first spec to reach them failed nine of its ten tests at once; the rest sat broken in specs the fail-fast run never got to. This reads every literal `SectionCard` title, derives both header names it can produce (`Collapse…`/`Expand…`), and fails in under a second naming the spec file:line. It covers the text-content matcher too — `button:has-text("Run analysis")` also matches the header of the `<SectionCard title="Run analysis">` that wraps the real control, and `:has-text` has no exact form. Fix at a finding is `exact: true`, or the control's real role (a `ModuleTabs` tab is `role="tab"`, not `"button"`). Titles computed at render time are reported as a NOTE — only the browser run sees those. Since 2026-09-03 it also flags `locator("<tag>").filter({ hasText: … })` — a bare element type narrowed only by SUBSTRING text matches every `<tag>` on the page carrying the word, and `.first()` picks whichever is earliest in the DOM, which changes the day a surface above it renders the same word: five KPI-tile locators read `locator("button").filter({ hasText: label })` until the recommendation slider arrived carrying "traffic_quality - reach without qualified action" and the Reach test hovered that instead, off-screen inside the rail, failing with a message about the popover rather than the locator. An ANCHORED regex (`/^Segment$/`) is exempt — `^` is what `exact: true` buys. Fix is a `data-testid` scope.
- `pnpm --filter @workspace/scripts run apply:ad-performance-views` — applies the three `ad_performance` aggregate views and NOTHING else. Use this, **not** `import:metrix`, to get that DDL into a database: the importer also re-imports the source data packages and in prod mode DELETES AND REPLACES all managed-account data, which is the wrong tool by orders of magnitude for adding three views (its `--env` + `IMPORT_ENV=production` two-factor gate is the only reason pointing an operator at it was merely wrong rather than destructive). The SQL is not written in the script — it is extracted verbatim at runtime from `schema.sql` between the `AD_PERFORMANCE_AGGREGATE_VIEWS_BEGIN/END` sentinels, so the two cannot drift — then scanned for `drop`/`delete`/`truncate`/`alter table`/`insert`/`grant` and REFUSED before connecting if any appear (comments are blanked first, so prose about deleting doesn't false-positive). Runs in one transaction, touches no row data, and re-reads the catalogs afterwards because "the statements ran" and "the views are correct" are different claims. `-- --dry-run` prints the SQL without executing or connecting.
- `pnpm --filter @workspace/scripts run check:ad-performance-views` — READ-ONLY operator check (not a `.replit` validation, same as `check:db-credentials`: it needs a credential). Confirms the three `ad_performance` aggregate views exist, that each carries `security_invoker = on`, and that `anon`/`authenticated` are denied SELECT. The load-bearing assertion is `security_invoker`: without it a superuser-created view reads the base table with the OWNER's privileges, bypassing RLS and handing every account's rows to anyone who can select the view — the exact hole the RLS block exists to close, reopened through a side door. It is one word in the DDL and invisible to a "do the views exist?" check. Prints no credential material (host:port only), so output is safe to paste. Exit 0 pass / 1 missing-or-unsafe / 2 no credential resolved (nothing checked — not a verdict on the DB). Run it where the credential already lives; cloud Claude Code environments are NOT a secrets store.
- `pnpm --filter @workspace/scripts run check:seed-fixture-drift` — validation step (`seed-fixture-drift`): logs in via the demo account (`DEMO_ACCOUNT_EMAIL` / `DEMO_ACCOUNT_PASSWORD`), fetches the live seed from the running API server, and compares its structural key shape against the checked-in fixture (`artifacts/metrix-iap/src/test-fixtures/metrix_seed_bundle.json`). Exits 1 with a diff if the shape has drifted so IAP tests can never silently pass against a stale snapshot. Requires the API Server workflow to be running and `DEMO_ACCOUNT_PASSWORD` to be set.
- `pnpm --filter @workspace/scripts run refresh:seed-fixture` — overwrites the checked-in fixture with a fresh seed fetched from the running API server (same auth as above). Run this after any seed schema change, then commit the updated fixture.
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/scripts run import:metrix` — (re)apply Metrix Supabase schema and (re)import source data packages (`scripts/data/metrix/`); idempotent. Asserts CSV internal consistency and aborts loudly on drift. Backfills `ads.meta_ad_id`/`creative_asset_url` from a per-account `meta_ads_export.json` when present.
- `pnpm --filter @workspace/scripts run enforce:importer-rls` — idempotent: enables RLS on all 39 importer tables and revokes anon/authenticated grants so the browser-embedded anon key gets a hard 401 on every table. Run after any new table is added to `schema.sql`. The full importer already runs this block as part of the schema step; this command is for standalone re-enforcement without re-importing all data.
- `pnpm --filter @workspace/scripts run create:user x@y.com [password]` — create/reset a Metrix IAP user account (prints temp password if none given; forces password change on first login)
- `pnpm --filter @workspace/scripts run migrate:metrix-official` — apply the official METRIX 22-table schema to Supabase (migrations immutable/checksummed; policies re-applied every run)
- `pnpm --filter @workspace/scripts run mirror:auth-users` — backfill Replit Postgres users into Supabase Auth (idempotent)
- Required env: `DATABASE_URL` (Replit Postgres, waitlist), `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` (API server reads Metrix data)
- Required secret: `SUPABASE_DB_URL` (Metrix data importer)
- Optional secret: `ADMIN_API_KEY` — gates `GET /api/metrix/agent-waitlist`; fails closed (401) when unset
- Optional secret: `RESEND_API_KEY` — enables outbound email; without it, actions still complete and the server logs an explicit "skipped" warning. Optional `REQUEST_ACCESS_FROM_EMAIL` overrides the Resend sender
- Optional secret: `DEMO_ACCOUNT_PASSWORD` — enables the self-healing demo login (`demoAccountSafeguard.ts`): on every API-server boot the demo account (`demo@metrix.app` by default, override with `DEMO_ACCOUNT_EMAIL`) is created/repaired with this exact password — admin role, enabled, never `must_change_password` — so it survives DB resets, rollbacks, and the dev/prod split. When unset, nothing is provisioned (logged as skipped).

## Auth (Metrix IAP)

- Custom auth: bcryptjs + DB-backed sessions (`user_sessions`, sha256-hashed tokens, 30-day expiry) in an httpOnly `metrix_session` cookie. Routes: `/api/metrix/auth/{login,logout,me,change-password}`.
- Unauthenticated visitors see a login page with "Request access" (→ marketing sign-up form, Supabase `request_access`) and "Learn more" links. All sign-ups go through that form; the `agent-waitlist` endpoint remains only for admin flows.
- Admin approval (Settings → Metrix Agent waitlist, gated by `ADMIN_API_KEY`; or standalone `/admin` console gated by `ADMIN_PANEL_PASSWORD` with a signed `metrix_admin` cookie) provisions a user with a temp password, emails it via Resend, and falls back to an on-screen copy button if email fails. Strict lifecycle: only `pending` entries transition (approve/reject after the other → 409).
- Email delivery goes through `artifacts/api-server/src/lib/email.ts` (`sendEmail` → sent/skipped/failed + reason; detects Resend sandbox 403s). `GET /api/metrix/admin/email-status` reports mode + environment for the admin console banner.
- Admin user management (`requireAdmin`): resend temp password, send password-reset link, revoke/restore accounts. Disabled users are rejected everywhere with generic (non-enumerating) messages.
- First login with a temp password forces a password-change screen; changing password revokes other sessions.
- Self-service reset: "Forgot password?" → `/forgot-password` (neutral response) → Resend link → `/reset-password?token=...` (single-use, 1h expiry, revokes all sessions).
- Brand: shared logo components in `src/components/brand/BrandMark.tsx` (IAP) and marketing equivalent; auth screens/Topbar/emails all use the real `metrix-logo.png`.
- All `/api/metrix/seed` and `/api/metrix/workspaces/:workspaceId/*` routes require a session; workspace routes verify `workspaceId` matches the seed's manager account id (single-workspace deployment).
- Settings → Team & Access shows real provisioned accounts merged over the seed roster. Sign out lives in Topbar + Settings → Account (also has a "Password" card). Login rate limit: 20 attempts / 10 min per IP+email.
- Per-user account authorization: `users.role` (admin|member) + `user_ad_accounts` grants. Admins see everything; members see only granted accounts and their own generated reports. Members/invites endpoints are admin-only.
- Agency admin safeguard (`agencyAccessSafeguard.ts`): designated agency emails (`AGENCY_ADMIN_EMAILS`, default `meta@metamktgagency.com`) are always reconciled to `role: admin` on boot and on provisioning, never scoped by grants — prevents the agency's own login from ending up as a scopeless member.

## METRIX official schema

- The official 22-table METRIX schema (identity/cohorts/runs/outputs/intake/alerts/review/learning + registries) is deployed via `migrate:metrix-official`. Migrations are immutable once applied (checksum drift aborts); policies (`supabase/policies/`) are idempotent and re-applied every run — evolve security there.
- Legacy importer table `creative_briefs` was renamed `imported_creative_briefs` (official schema owns the `creative_briefs` name).
- RLS on all 22 tables via security-definer tenancy helpers: members read their clients, owner/operator write, viewer read-only; audit tables append-only; config-as-data tables read-only to authenticated; `anon` fully denied.
- Learning gate: `learning_registry` writes require a matching, run-scoped `approval_events` row, enforced by a BEFORE INSERT/UPDATE trigger (fires even for BYPASSRLS roles).
- Hard DB constraints: no ROAS alert rules, BSIL suggestions campaign/ad_set scope only, manual creative intake ≥ 5 assets.
- Approving a user also provisions a Supabase Auth user via `@workspace/auth-mirror` (idempotent, non-fatal on failure) for FK targets only — login stays custom session auth.
- Security tests: `artifacts/api-server/src/lib/__tests__/metrixOfficialSecurity.test.ts` (rolled-back transactions, role impersonation) — fail loudly if the official schema isn't deployed.
- Importer schema RLS: the importer tables (`scripts/src/metrix-supabase/schema.sql`, ad data + `request_access` PII) are reached only by the API server's service_role key, but PostgREST still exposes `public` tables to the browser-embedded anon key. An idempotent RLS block at the end of `schema.sql` enables RLS (deny-by-default) and revokes anon/authenticated grants on every importer table so the anon key gets a hard 401; service_role/superuser (BYPASSRLS) are unaffected.

## Architecture decisions

- Metrix data lives in Supabase Postgres; the API server assembles a seed bundle at request time (5-min cache; every in-app mutation invalidates it explicitly, so the TTL only bounds out-of-band writes) and returns 503 if Supabase is down — no static fallback by design.
- Seed assembly is fully account-aware (no hardcoded ids): `buildAccountObject()` builds any account generically, honest pending shape until it has real data. Manager totals sum across accounts. `invalidateMetrixSeedCache()` busts the cache.
- **`concept_rollup` and `v3_variable_performance` are cumulative — scope before you aggregate.** `schema.sql` widened both tables' unique keys to include `manual_analysis_run_id` so re-running analysis accumulates history rather than destroying it (RunScopePicker reads that history), which means the arrays they feed hold one row per run. Summing them unscoped counts the same spend once per run: the Creative DNA page showed $60,704 for a token that had spent $26,869, and the client-facing report listed every variable once per run. Use `scopeToRun(rows, analysis.latest_analysis_run_id)` from `lib/run-supersede.ts`, or the page's own `runSelection` where a RunScopePicker is present; rows with a null run id are pre-migration history and must always be kept. Nothing at the point of use says any of this, which is why it went wrong in four places — the only reason one surfaced is that React warned about the colliding keys. `performance_by_cell` and `placement_signal` are NOT run-keyed (one row per (cell, result type) and per (platform, placement)), so folding those is a different and safe operation.
- Selecting a live Meta ad account registers it in Supabase `ad_accounts` (insert-only, `status: "unconfigured"`) so it appears immediately with an honest "analysis not run yet" state; promotion to `configured` happens only when real analysis data lands.
- `optimization_loop`/Creative Scan stay empty/pending until those stages actually run — UI never fabricates data. Same principle applies to account-level totals overrides (e.g. LittleData): authoritative totals are stated separately from ad-level coverage gaps, never blended dishonestly.
- `ads.creative_asset_url`/`meta_ad_id` are nullable, backfilled via a per-account `meta_ads_export.json`. The client resolves the primary ad per creative cell (`primaryAdForCell` in `creative-assembly.ts`); "View in Ads Manager" enables only when both the numeric Meta account id and `meta_ad_id` exist (never the internal account id).
- **Creative components (copy-level intelligence), modular by source.** `artifacts/api-server/src/lib/creativeComponents.ts` is pure: every creative input is an `AdCreativeInput` tagged with its `source` (`performance_export` today; `uploaded_asset` and `meta_api` are producers of the same shape, merged per field by `SOURCE_PRECEDENCE` — uploaded asset > Meta API > export). Seed assembly turns `ad_performance.ad_creative_metadata` (headline, primary text, description, CTA, destination, media name — captured on every run) into `account.creative_components` (per family, each distinct value weighted against the ads that carried it: `weight` = result share × efficiency index normalised to the family's best; cost per result null without results, never $0) and `ads[].creative`. The analysis engine writes three additive columns on `concept_performance`: `creative_coverage_pct` (share of the concept's spend on ads with known copy), `evidence_grade` (full ≥ 80% · partial · none) and `confidence_score` (the volume tier's score × (0.7 + 0.3 × coverage)). The categorical `confidence_level` is NOT relabelled by evidence — sample size is sample size — the score and grade carry it; rows computed before the columns read null and render "not graded", never "no evidence". UI: Creative Library "Copy components" tab (stands in when no scanned library exists — the page is blank only when neither exists), copy in the Creative dialog named by source, and `CreativeSourceNudge` (upload creatives / connect Meta) shown while no visual creative exists, dismissible per account per browser (`creativeNudgeStore`). Runs stay manual.
- **Staged file bytes are read one file at a time as PostgREST binary output — never `select content` for a list of rows, in the run, the `/file` route OR the deconstruction start (91 creatives in one statement hit the statement timeout on 2026-09-02).** `lib/supabaseBinary.ts` fetches one cell with `Accept: application/octet-stream` through the domain-typed RPCs `manual_import_content` / `manual_import_chunk_content` in `schema.sql` (PostgREST 12+ serves raw bytes only for a function returning a domain named after the media type — a table column or a plain `bytea` return is refused with 406; on a 406 the module falls back to ONE row's JSON content and logs it), and `loadImportContentBuffer` is the only reader (inline row or `manual_import_chunks`, byte count checked against `size_bytes`). Why: on 2026-09-02 the first fresh-account run selected the full `content` of every staged performance file in one query; PostgREST hex-encodes bytea and aggregates it in one backend, the instance ran out of memory, every REST request returned 522 for over an hour, and the app sat on its boot splash because the seed could not load either (register §13.1). The splash now has a deadline: past 20 s it says the data service has not answered and offers a retry that cancels the hung request first.
- **Creative filename → ad-name mapping is the server's job.** `lib/creativeAutoMap.ts` runs the matcher (`lib/adNameMatch.ts`, byte-identical to the client copy — `scripts/src/adname-match-drift.test.ts`) at staging against the ads the account already knows, after every successful analysis run against the registry it just wrote (`syncAllCreativeLinksForAccount` calls it first), and on `POST …/sync-creative-links`. Candidates are the ad name plus the Meta image / video names the export recorded for it; cell codes (C1A, C2B) are identifiers that decide the match, and only an identifier or a confident similarity match is ever applied — a guess is a suggestion for the editor, never a link (17 unrelated files once landed on one ad through the guess tier). The upload dialogs send no mapping, never block on unmapped files and never offer to delete them; the ad-name editor remains for corrections. `CreativeNextStepNudge` then suggests deconstructing staged creatives and re-running analysis with the full variable library — suggestions only, runs stay manual.
- **Reconciliation-first evidence layer (spec: `docs/specs/iap-multi-report-reconciliation.md`).** Every staged report is classified by what it can PROVE (`reportGrain.ts`, stored as `manual_imports.report_grain`), reduced to observations at Account ID + Ad ID × segment × period (`reconciliation.ts`), and reconciled per additive metric against the strongest compatible control (Ad Summary per Ad ID → daily summary → name-keyed summary through a registry-proven unique name → Meta's totals row → none) into `reconciliation_ledger` with SIGNED residuals; residuals never become rows, never fold into Unknown, and nothing is scaled. Ad names are not identifiers (the validated account has 44 Ad IDs under 19 names); a name joins Ad-ID data only when the registry proves it unique. Duplicated headers are verified row by row (identical → note; different → schema conflict, the field unusable for joins). Asset columns are classified by row variation (context vs breakdown); several varying together attribute to a copy signature, never to one field. No report class is mandatory — a run needs one delivery report with spend; every other export adds resolution. The modelled tier (`balanceMatrix.ts`) exists as a tested interface and emits nothing. Confidence on the new rows uses the DOCUMENTED bands (`confidenceLevel`: high > 100 conversions or > $1,000; medium 10–100 or $100–1,000), which differ from the shipped concept tier — register §14 decision. Client: creative dialogs join through `ads[].meta_ad_ids` first, cell second (`useCreativeEvidence`); the Demographics/Placements/Funnel/Evidence tabs, the Command Center's Reconciliation panel and the Audience coverage tile all carry an evidence state. Live cross-check: `pnpm --filter @workspace/scripts run check:reconciliation-ledger -- <account_id>` (read-only, credentialed).
- **Metric expectations are per CSV class.** The Ad Summary export is a ledger (full spend and results per ad-day, cross-checked against the pivots) and is judged only on Amount spent · Impressions · Reach · Results · Result type (`expectedBaseMetricsFor` / `coreBaseMetricsFor` in `iapCsvSpec.ts`); engagement/video columns are accepted when present and never reported missing or graded against it. The demographic and placement pivots keep the full base list.
- Manual accounts: `POST /api/metrix/accounts` creates an unconfigured account and grants the creator; `POST /api/metrix/accounts/:id/manual-imports` stages raw uploads (bytea, 75 MB decoded limit single-request) — never parsed at upload time. `AddAccountDialog` is the single real entry point (Meta OAuth or manual + uploads).
- Chunked large uploads: performance report files up to **150 MB** go through `POST …/manual-imports/uploads` (init, `status='uploading'`) → `PUT …/uploads/:id/chunks/:n` (~8 MB base64 chunks, decoded ≤16 MB each) → `POST …/uploads/:id/complete`, which assembles from `manual_import_chunks` (bytea rows, cascade-delete with the import), verifies announced size, and runs the IDENTICAL validation + md5 dup guard as single-request staging before flipping to `staged`. Why chunked: the deployment proxy rejects big single bodies with a bare 413 before Express sees them, and the single-request path OOM'd historically at 150-200 MB from base64+JSON+hex payload multiplication — do NOT "fix" large uploads by raising express limits. Readers use `loadImportContentBuffer` (chunk-aware; inline `content` when present). `uploading` rows are excluded from listings and never consumed by runs; stale sessions sweep after 24h. Client switches transports above 20 MB automatically (creative assets stay single-request, 75 MB).
- Manual performance requires two exact Meta pivot CSV exports (`performance_demo_csv`, `performance_placement_csv`), spec'd in `iapCsvSpec.ts` and parsed by `iapCsvParser.ts`. Creative uploads are staged individually (no ZIP) with an editable, correctable `ad_names` mapping per file.
- The manual upload dialog requires both CSVs staged plus an explicit "Review" confirmation before closing — nothing silently finalized. Date-range selection lives only in the separate "Run analysis" step, never in the upload dialog.
- Manual analysis is never automatic: a signed-in user with account access must pick a date range and press "Run analysis" (`POST /api/metrix/accounts/:id/analysis-runs`, 202 + `run_id`). Follows the running/success/error honesty pattern (partial unique index blocks concurrent runs; stale `running` rows flip to `error`). Date window anchors to the latest date found in the data, not wall-clock time.
- Waitlist + request-access stay on Replit Postgres (Drizzle); Supabase is only for Metrix IAP data.
- Live Meta connection (pilot): OAuth via Meta Graph v23.0, `ads_read` scope only. Tokens AES-256-GCM encrypted (`TOKEN_ENCRYPTION_KEY`); OAuth state HMAC-signed (`SESSION_SECRET`, 15-min expiry). Report pulls insert as `running`, flip to `success` only after all rows commit (partial rows deleted on failure). Once a live connection exists, demo/seed integration panels are hidden — live and demo data never mix.
- In-app Strategy/Briefs generation: `POST /api/metrix/accounts/:id/generate/{strategy,briefs}` (202 + `run_id`, background job) via `generationEngine.ts` — claude-sonnet-4-6 through the Replit AI integration, evidence packs from real Supabase analysis rows, zod validation + one repair retry, hallucinated refs dropped. Generated rows (`source='generated'`) fully replace imported rows for that kind (never merged); same running/success/error honesty pattern; only one running run per account+kind.
- Generated reports (`workspace_reports`, Replit Postgres) store a full document snapshot at generate time so History/Exports reproduce it exactly; deletable from Report History (workspace-scoped).
- The IAP Loop is execute-on-command, never automatic. Data ingestion (live Meta pulls, manual uploads) refreshes data but must never trigger a loop run; the interface only recommends the next runnable stage for the user to execute.
- Manual analysis ingestion is **idempotent rebuild**, not upsert: each date-scoped rollup table (`ad_performance`, `demographic/placement/platform/device_performance`) is cleared for the run's `[dateStart, dateEnd]` window immediately before its own insert, every batch is validated BEFORE the first destructive delete (`buildAdPerformanceRows` rejects non-ISO dates and duplicate unique-key tuples with actionable messages), and replaced-row counts surface as a run warning (`[Re-run] Replaced N…`) so superseding is never silent. Re-staging a corrected file for the same window supersedes the earlier rows by design; multi-file-per-slot staging stays additive across *different* windows. `Day` values are normalized to `YYYY-MM-DD` at parse time (`normalizeDayValues`: per-file M/D/YYYY vs D/M/YYYY disambiguation from component evidence, ambiguous files hard-422 rather than guessed) because bucket keys, lexicographic window math, the window-delete predicate, and Postgres date-typed unique keys all assume ISO — unnormalized dates were the root cause of the Aug 2026 AAFE re-ingestion `duplicate key` failure. Scientific-notation ID cells (Sheets round-trip corruption) are blanked with a warning on the CSV path too, mirroring `xlsxToCsv`'s guard. `computeDataCoverage` also fails reconciliation loudly when a breakdown class's windowed spend exceeds the daily-attributable baseline (>101%, aggregate-shape summaries exempt) — the duplicate-ingestion signature. Analysis-completeness module counts scope to the latest SUCCESSFUL run (a failed latest run has no outputs by definition and must not read as "0 rows everywhere"). Multi-sheet XLSX uploads pick the sheet whose header actually matches the target class's required columns.

## Gotchas

- Resend sandbox sender (`onboarding@resend.dev`) only delivers to the Resend account owner's inbox — sends to other recipients get rejected with 403 until a domain is verified and `REQUEST_ACCESS_FROM_EMAIL` is set. The admin console banner and `email_error` fields surface this live.
