What was broken, now fixed





Analysis ran but didn't populate the interface (the big one). The engine wrote demographic_performance and delivery-basis placement/platform/device rows — but the Audience and Placements views only read the importer-shaped demographic_signal/placement_signal tables. A manual account showed "No demographic signal" / "No placement signal" forever, even after a successful run. The engine now also writes those signal tables in the exact shape every existing render path expects, so the Audience and Placements modules populate from your uploaded CSVs. It also registers the analysis_core loop stage. Note: existing manual accounts need one analysis re-run to backfill these surfaces.



Strategy generation was ungrounded for manual accounts. The evidence pack fed to the model read those same empty tables, so "Generate strategy" ran on almost nothing. It now receives the demographic and placement signal plus a per-ad performance rollup (ad names carry your creative vocabulary), so the strategy → MST brief chain is genuinely grounded in the uploaded historical data.



Destructive-risk gap: nothing stopped a manual analysis run against an importer-backed or live-Meta account, where its full-refresh deletes would have destroyed that pipeline's rows. Runs are now guarded to manual-reports accounts only.



The downloadable sample CSVs were malformed — header columns containing commas (e.g. "CPM (cost per 1,000 impressions)") weren't quoted, so the product's own sample failed its own upload validation. Found by the new round-trip test; fixed.



Test suite was red on main (3–4 failures): missing ResizeObserver stub crashed chart-bearing views under vitest, a race in the creative-mapping test, and stale assertions from the Placements redesign. All fixed — 19/19 files, 346/346 tests pass, plus a new end-to-end engine test driving the real analysis pipeline against an in-memory Supabase stub.
