Context & Objective
Act as an Expert UX/UI Frontend Engineer. My platform is a highly complex, data-rich SaaS analytics dashboard (dark mode). The current UI is too dense and overwhelming. Our primary objective is to refactor the entire frontend to dramatically improve navigability and usability by implementing Progressive Disclosure.

You will analyze the current components and refactor them to compress data, increase whitespace, and standardize how users drill down into information.

Core Architectural Directives

1. Implement the "Three-Layer" Information System
Refactor all dashboard views to follow this strict hierarchy:

Layer 1 (The Glance): Default views must only show primary KPIs, aggregated totals, and simple trend indicators (e.g., green/red arrows). Remove heavy data tables from the immediate top-level view.

Layer 2 (The Hover): Implement lightweight tooltips (onMouseEnter) for all secondary context. Metric definitions, exact data points on charts, and truncated text must be hidden behind a hover state.

Layer 3 (The Click): All complex raw data, full tables, and granular creative breakdowns must be hidden behind a standardized click action.

2. Standardize Drill-Down Patterns
Stop using mixed interactions for deep dives. Enforce the following UI patterns across all modules:

Side Panels (Drawers): Whenever a user clicks a specific audience segment, creative card, or campaign row to see more details, open a right-aligned sliding panel (Drawer). Do not use expanding inline cards that disrupt the grid layout. Keep the main dashboard visible beneath a dark, semi-transparent overlay.

Expanding Rows (Accordions): For multi-level data tables (e.g., a campaign with multiple ad sets), use an accordion row expansion rather than navigating to a new page.

Modals: Restrict modals only to isolated actions (e.g., editing a budget, deleting an asset, confirming a setting). Do not use modals for viewing analytics.

3. Widget & Module Restructuring

Ensure every dashboard module/card answers only one question.

Cap list items inside summary widgets at 5 items max. Add a persistent "View All" button to route to the deeper table/Drawer.

Replace heavy, axis-based charts in overview cards with minimalist sparklines.

4. Data Table UX
Refactor all existing tables to include:

Sticky headers (position: sticky, top: 0) so context is never lost when scrolling vertically.

Sticky first columns (usually the Asset Name or Campaign ID) for horizontal scrolling.

Increased internal cell padding (whitespace) to let the data breathe.

Execution Plan
Please acknowledge these rules. Then, scan my current component directory (specifically focusing on the Data Table, Sidebar Navigation, and Data Card components) and provide a step-by-step refactoring plan starting with creating the global reusable Drawer and Tooltip components.
