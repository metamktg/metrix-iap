2. Replace raw variable-code labels with human-readable descriptors

Visible raw strings like:
HK_Authority + TN_Aspirational: winning hook stack

Should become:
Authority Hook + Aspirational Tone
Winning hook stack for transformation-led creative.

Rules:
- Use the IAP variable registry or existing repository mapping to resolve raw codes into labels.
- Keep raw codes only as small mono chips or hover metadata.
- Never use raw CN_, FW_, TN_, HK_, PR_, HP_, ST_, AW_ codes as the main user-facing title when a human-readable label exists.
- If no descriptor exists, gracefully generate a readable fallback by removing the prefix and formatting the remaining string.
- Add a utility resolver such as:
  - resolveVariableLabel(code)
  - resolveVariableDescription(code)
  - resolveVariableStackLabel(codes[])

Examples:
- HK_Authority → Authority Hook
- TN_Aspirational → Aspirational Tone
- FW_PAS → Problem-Agitate-Solve
- CN_ProductDemo → Product Demo
- PR_VisualDemo → Visual Demo Proof

4. Suggestion workflow upgrade

Replace static suggestion lists with an interactive card workflow.

Create or refactor components:
- SuggestionDeck
- SuggestionCard
- SuggestionDetailDrawer
- TaskTray
- DismissedLog

Interactions:
- Approve: swipe/right click/button → moves suggestion to Task Tray
- Reject: swipe/left click/button → moves suggestion to Dismissed Log
- Details: swipe up/click Details → opens source-backed detail drawer
- Undo: restores most recent action

Desktop interactions:
- Approve button
- Reject button
- Details button
- keyboard shortcuts:
  - Right arrow = approve
  - Left arrow = reject
  - Up arrow or Enter = details

Mobile/touch interactions:
- horizontal swipe approve/reject
- vertical swipe or tap for details

Data rules:
- Suggestions must remain data-backed.
- BSIL budget suggestions must remain campaign/ad-set scope only.
- Do not create creative-level BSIL budget suggestions.
- Approved suggestions do not auto-apply changes.
- Approved suggestions become manual implementation tasks in the Task Tray.
- Rejected suggestions remain visible in Dismissed Log with restore option.

Each SuggestionCard should show:
- human-readable recommendation title
- short rationale
- impact level
- confidence/source chip
- scope chip: campaign, ad_set, creative, audience, placement, brief, mst
- raw source ID collapsed or hidden behind Details

7. Dynamic creative placeholder architecture

Define and implement reusable asset preview components.

Create:
- CreativePreviewCard
- CreativeAssetGrid
- CreativeFallbackState
- AssetSourceBadge
- VariableDescriptorChips

Asset preview should support:
- image
- video thumbnail
- carousel
- unknown/missing media
- metadata pending
- source not connected

Data model expectation:

type CreativeAssetPreview = {
  asset_id: string;
  source_platform: "meta" | "manual_upload" | "drive" | "canva" | "unknown";
  external_creative_id?: string;
  ad_id?: string;
  thumbnail_url?: string;
  media_url?: string;
  media_type: "image" | "video" | "carousel" | "unknown";
  concept_code?: string;
  angle_codes?: string[];
  human_label?: string;
  fallback_state: "ready" | "missing_thumbnail" | "metadata_pending" | "not_connected";
};

Trigger logic:
- Analysis pages should request creative previews by ad_id or creative_id when rendering creative-related signals.
- Concept Library should request assets by concept_code or concept_family_id.
- Creative Map should request assets by node/concept/angle relationship.
- Report Builder should render only selected or report-safe creative examples.
- Strategy should render source creatives attached to ICPs, pillars, or hypotheses.
- Brief Builder should render reference creatives attached to the source insight or concept.
- MST should render assets by matrix position once MST setup exists.

Do not fetch assets globally on app load.
Fetch on route/page load and cache by asset_id.
If an asset fails, render fallback state without breaking the page.

9. MST architecture

The MST page should not pretend there is completed MST performance if no MST has run.

Refactor MST into a clear staged experience:

A. Historical Signal Summary
- strongest historical concepts
- strongest historical hooks/tones/frameworks
- confidence score
- source analysis run

B. First Sprint Builder
- proposed C1-C4 concept families
- proposed A-D angle rows
- proposed variable stacks
- missing asset/data requirements
- validation status

C. Generate First MST Brief
- button or CTA to generate first MST brief from historical IAP data
- creates draft brief, not live campaign changes
- output routes to Brief Builder or MST Draft Brief state

D. MST Coming States
- Pending setup
- Pending assets
- Pending validation
- Ready for launch
- Results pending

MST must respect matrix logic:
- columns = concepts / ICPs / concept families
- rows = angle approaches
- each creative has a unique matrix position
- variable stacks must be tracked
- do not reuse concept-angle codes incorrectly
