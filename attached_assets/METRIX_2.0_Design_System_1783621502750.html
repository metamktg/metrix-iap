01 · Design Philosophy

Intelligence
Made Legible

Metrix 2.0 operates in a high-stakes decision environment. Every visual choice either earns the operator's trust by making complex data immediately readable, or erodes it by adding friction. The design philosophy is built on three non-negotiable commitments.

1
Principle 01
Signal over Decoration
Every pixel earns its place. Visual elements exist only to direct attention, encode meaning, or support a decision. Colour is not applied for aesthetics — it is the data. The gap between green and amber is a budget decision, not a design preference.
2
Principle 02
Density with Clarity
Agency operators and brand owners manage multiple accounts simultaneously. The interface must carry high information density without creating visual noise. This is achieved through strict typographic hierarchy, intentional whitespace, and progressive disclosure — not by reducing content.
3
Principle 03
Act, not View
The v1 interface delivers reports. The v2 interface delivers decisions. Every page must answer "what do I do now?" before the operator asks. Analysis flows to strategy, strategy flows to briefs, briefs flow to actions — and every action has a visible path to execution within the same workspace.

02 · Interface Architecture

Unified Shell,
Contextual Canvas

The canvas within is contextual — its density, layout, and interaction model adapts to the page type. Operators learn the shell once, and navigate content fluently across all accounts.

Page Type Taxonomy

Four distinct layout modes, each optimised for a different cognitive task. The page type dictates density, column structure, and interaction affordances.

⊞
Type A — Command
High density · multi-panel · status-first
The operational dashboard. KPI grid, intelligence briefing banner, action queue, platform split, and copy performance all visible at once. The operator gets the full picture before deciding where to go. Grid is fluid and responsive — panels reflow as viewport narrows.
Overview Listen
◎
Type B — Intelligence
Analytical depth · dual-column · evidence-led
Analysis and audience pages. Priority-read cards at top anchor the key finding. Below, dual-column layout balances chart/table data with narrative explanation. Progressive disclosure hides lower-confidence sub-findings. Toolbar allows audience filtering without leaving the page.
Analysis Creative Intel Audience Intel
▶
Type C — Action
Decision-focused · single-column · confirmation-gated
Recommendations and Brief Builder. One action at a time. Each card is a complete decision unit — evidence, confidence, owner, time estimate, and a gated CTA. Destructive actions (pause, kill) show a confirmation overlay before writing. Every execution is logged to the audit trail.
Recommendations Strategy Map
◧
Type D — Builder
Step-through · guided · structured output
Brief Builder and Report Builder. Multi-step wizard pattern with persistent left-rail progress indicator. Each step is a focused form or selection. Output preview updates in real time in a right-column panel. Export and share actions live in a sticky footer CTA bar.

03 · Component Library

Modular by
Design

Four layers of composition. Tokens set the design constraints. Primitives implement them. Compounds combine primitives into functional units. Compositions assemble compounds into complete page sections. Nothing exists outside this hierarchy — every new component must justify which layer it belongs to.

04 · Operational Workflow

The Intelligence
Loop

Metrix v1 is a destination. You arrive, you read, you leave. Metrix v2 is a loop. Analysis flows to strategy. Strategy generates briefs. Briefs become tests. Tests feed the next analysis cycle. Every page in the interface is a stage in this loop — and the operator always knows which stage they are in.

From Report Viewer to Operator Workspace

Six specific transitions that define the v1 → v2 upgrade. Each is a behavioural shift, not just a visual change.

v1 · Current
Static Analysis Reports
IAP outputs are rendered once at generation time. The operator reads a snapshot. Interactivity ends at "open modal."
→
Closes with
v2 · Target
On-Demand Intelligence Refresh
Operators trigger lightweight analysis refreshes from Command Center. Full IAP cycles run on schedule or on-demand. Outputs are versioned — diff view shows what changed since last run.
v1 · Current
Today's Priorities (text list)
Three static list items on Command Center. No prioritisation engine, no interaction model beyond "click to modal."
→
Closes with
v2 · Target
Action Queue (Priority-Sequenced Swipe)
8 evidence-bound actions, sorted P0/P1/P2. Tinder-style swipe triage. Skip or add to task tray. Keyboard-navigable. Each card carries confidence, owner, time estimate, and a direct path to execution. Already shipped in v13 pass 4.
v1 · Current
Raw Variable Codes
CN_IceColdDrip, HK_DirectStatement — variable chips render as raw IAP codes. Legible only to those who built the system.
→
Closes with
v2 · Target
Human-Readable Variable Chips
VAR_DICT maps all codes to labels + descriptions. Chips read "Ice Cold Drip" not "CN_IceColdDrip." Prefix tag retains the code. Hover reveals full description. Client-facing ready. Already shipped in v13 pass 4.
v1 · Current
Disconnected Brief Builder
Briefs are built manually by the strategist. No direct link from analysis insight to brief generation. The operator must connect the dots across pages.
→
Closes with
v2 · Target
IAP-Generated Brief Templates
Every action card with lane=test or lane=validate auto-generates a pre-filled brief template from the IAP variable stack. Strategist reviews, refines, and exports. Brief ID references the originating insight record. Full traceability.
v1 · Current
No Execution Guardrails
Scale/kill/pause actions in the interface currently navigate to a detail modal. No confirmation step, no audit log, no write protection on destructive actions.
→
Closes with
v2 · Target
Confirmation-Gated Execution
Kill and pause actions require a 2-step overlay: intent (what will change) → confirm (write to Meta Ads API). Budget modifications show before/after CPA projections. All writes log to the Audit Trail with timestamp, confidence, owner, and evidence reference. No one-click destructions.
v1 · Current
Single Account, Single Session
One account active at a time. Agency operators switch accounts manually. No cross-account overview or portfolio view.
→
Closes with
v2 · Target
Agency Portfolio View
Account switcher becomes a portfolio dashboard. Each account shows its current loop stage, open action count, and confidence trend. Urgent items surface across all accounts in a unified alert rail. Agency operators manage 10–20 accounts from a single view without losing per-account context.
◈
Design as Competitive Moat

The Metrix 2.0 design system is not a visual upgrade. It is a product strategy. The Intelligence Loop architecture means every operator interaction — from reading a report to pausing a bad ad — is captured, connected, and fed back into the next IAP cycle. Over time, this creates a data flywheel that becomes impossible to replicate from a standing start. The design system enforces the loop. Every component, every page type, every interaction pattern reinforces a single question: what do you do next? Agencies that run on Metrix will not want to leave. That is the brief.
